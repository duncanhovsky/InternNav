# 训练监控轨迹面板增强方案：重采样点、对应关系与图例开关

## 1. 目标

在训练监控网页的轨迹可视化面板中增加三类信息可视化：

1. 显示三次样条拟合轨迹上的重采样点。
2. 显示重采样点与预测轨迹航点之间的一一对应关系，用细线连接同下标点。
3. 支持轨迹面板元素显示/隐藏，交互方式参考 Loss 折线图：点击图例项即可切换对应图层。

本方案先不改动训练逻辑，只增强监控可视化与 JSONL 字段语义。

## 2. 现状梳理

### 2.1 前端入口

主要文件：

- `scripts/train/templates/monitor.html`

相关现有逻辑：

- `drawTrajectory(...)` 负责 Canvas 绘制。
- 静态图例位于 `.traj-legend`。
- `lastTrajData` 缓存当前样本，缩放、平移后通过 `renderCachedTraj()` 重绘。
- Loss 曲线使用 Chart.js，自带 legend 点击隐藏/显示数据集。

当前轨迹面板已经支持：

- 先验轨迹 `prior_traj`
- 真值轨迹 `gt_traj`
- GT 样条拟合曲线 `gt_spline_traj`
- 预测轨迹 `pred_traj`
- 障碍物点 `obstacle_pts`
- 导航目标 `nav_goal`
- 轨迹终点
- `theta_g` 方向辅助线

### 2.2 后端 snapshot 来源

主要文件：

- `internnav/trainer/bridgedp_trainer.py`

Bridge-DP 当前数据流：

- `_prepare_curve_supervision()` 使用 `_resample_trajectories_gpu(...)` 从 `batch_raw_labels` 生成固定长度监督点，并覆盖 `batch_labels`。
- 可视化写入时：
  - `gt_phys = _denorm_batch(batch_labels)`，本质上已经是三次样条弧长重采样后的监督点。
  - `gt_spline_traj = _resample_trajectories_gpu(batch_raw_labels, ..., predict_size * 4, include_start=True)`，是更密集的样条曲线。
  - `_write_traj_snapshot()` 已将 `gt_spline_traj` 写入 `traj_batches.jsonl`。

因此：

- “样条拟合曲线”可以继续使用 `gt_spline_traj`。
- “样条上的重采样点”可以直接使用当前 `gt_traj`，因为它就是训练监督用的固定长度重采样点。
- 为避免前端语义混乱，建议在 JSONL 中额外写入 `gt_resample_points`，值与 `gt_traj` 相同。旧字段保持不变，保证兼容。

## 3. 设计原则

1. 不增加训练计算负担：复用现有 `gt_phys` 和 `gt_spline_traj`，不重复拟合样条。
2. 保持向后兼容：旧 JSONL 没有 `gt_resample_points` 时，前端 fallback 到 `gt_traj`。
3. 图层状态只存在前端：切换显示/隐藏不影响数据文件和训练。
4. 对应关系按 waypoint 下标连接：`resample_points[i]` 连接 `pred_traj[i]`，不连接插入的公共原点。
5. 视觉层级清晰：障碍物和对应线在背景层，轨迹曲线和点在上层，目标/端点最后绘制。

## 4. 修改范围

### 4.1 前端：`scripts/train/templates/monitor.html`

重点修改：

1. 将静态 `.traj-legend span` 改为可点击图例项。
2. 新增前端图层状态对象，例如：

```js
const trajLayers = {
  prior: true,
  gt: true,
  gtSpline: true,
  resamplePoints: true,
  correspondence: true,
  pred: true,
  obstacles: true,
  navGoal: true,
  endpoint: true,
  theta: false,
};
```

3. 新增 `initTrajLegend()`：
   - 给每个图例项绑定 `click`。
   - 点击后切换 `trajLayers[layer]`。
   - 更新图例样式，如透明度、删除线、`aria-pressed`。
   - 调用 `renderCachedTraj()` 重绘。

4. 调整 `renderCachedTraj()` 和 `loadCurrentSample()`：
   - 读取 `d.gt_resample_points || d.gt_traj`。
   - 将重采样点单独传入 `drawTrajectory(...)`，或让 `drawTrajectory` 从 data object 中统一取值。

5. 重构 `drawTrajectory(...)` 参数：
   - 推荐改成 `drawTrajectory(canvas, data, layers)`，避免继续增长参数列表。
   - 兼容现有字段：
     - `data.gt_traj`
     - `data.gt_resample_points`
     - `data.gt_spline_traj`
     - `data.pred_traj`
     - `data.prior_traj`
     - `data.nav_goal`
     - `data.obstacle_pts`
     - `data.gt_valid_mask`
     - `data.pred_valid_mask`
     - `data.theta_g`

### 4.2 后端：`internnav/trainer/bridgedp_trainer.py`

轻量修改 `_write_traj_snapshot()`：

- 在每个 sample 中新增：

```python
"gt_resample_points": gt_phys[i].tolist(),
```

说明：

- `gt_traj` 保持原含义和原字段名，避免破坏旧前端或已有分析脚本。
- `gt_resample_points` 只是语义别名，便于前端明确区分“真值轨迹线”和“样条重采样点”。
- 如果之后希望显示原始未重采样轨迹，可再新增 `raw_gt_traj`，但本次需求不必引入。

### 4.3 NavDP 兼容

`internnav/trainer/navdp_trainer.py` 目前没有 `gt_spline_traj`。前端需要优雅降级：

- 没有 `gt_spline_traj` 时不绘制样条曲线。
- 没有 `gt_resample_points` 时用 `gt_traj` 绘制重采样点。
- 对应线只要求 `pred_traj` 和重采样点存在即可。

## 5. 图层与样式方案

### 5.1 图层列表

建议图例项：

| 图层 key | 默认 | 数据来源 | 样式 |
|---|---:|---|---|
| `prior` | 开 | `prior_traj` | 灰色虚线 |
| `gtSpline` | 开 | `gt_spline_traj` | 橙色实线 |
| `resamplePoints` | 开 | `gt_resample_points || gt_traj` | 橙色空心/实心小圆点，带细白描边 |
| `correspondence` | 开 | 重采样点 + `pred_traj` | 低透明度青色或灰蓝色细线 |
| `gt` | 开 | `gt_traj` | 绿色实线 |
| `pred` | 开 | `pred_traj` | 蓝色实线 + 朝向箭头 |
| `obstacles` | 开 | `obstacle_pts` | 红色半透明散点 |
| `navGoal` | 开 | `nav_goal` | 黄色菱形 |
| `endpoint` | 开 | `gt_traj[-1]` | 绿色圆点 + 白色外圈 |
| `theta` | 关 | `theta_g` + `nav_goal` | 绿色/橙色虚线箭头 |

### 5.2 绘制顺序

建议顺序：

1. 网格和坐标轴，始终显示。
2. 障碍物点。
3. 对应关系线。
4. 先验轨迹。
5. GT 样条拟合曲线。
6. GT 真值轨迹。
7. 预测轨迹。
8. 重采样点。
9. 导航目标、轨迹终点、起点、`theta_g`。

原因：

- 对应线容易变密，应放在背景层。
- 重采样点是本次新增重点，应压在曲线和轨迹线上方。
- 目标、起点、终点属于定位标记，应最后绘制。

## 6. 重采样点绘制细节

数据选择：

```js
const resamplePoints = toXYT(data.gt_resample_points || data.gt_traj, false);
```

注意：

- 不插入公共原点，避免下标与预测航点错位。
- 点的数量通常等于 `predict_size`，例如 24。
- 点可以使用半径 `3.5` 到 `4.5`，在当前 420x320 canvas 上不会太拥挤。
- 每隔 4 或 6 个点可以绘制小下标，默认不显示全部下标，避免文字遮挡。

建议样式：

- 填充：`#fbbf24` 或 `#fb923c`
- 描边：`#0f1117` 或 `rgba(255,255,255,0.85)`
- 当前图层隐藏时不绘制点，也不绘制点编号。

## 7. 对应关系线绘制细节

连接规则：

```js
const n = Math.min(resamplePoints.length, predPoints.length);
for (let i = 0; i < n; i++) {
  drawLine(resamplePoints[i], predPoints[i]);
}
```

注意：

- `predPoints` 也不要插入公共原点。
- 若存在 `pred_valid_mask`，可选择只连接有效预测点；默认建议：
  - 有效段：透明度较高。
  - 无效段：透明度更低或虚线。
- 对应线的颜色可以按误差大小渐变，但第一版建议使用统一低透明度，避免面板过花。

建议样式：

- `strokeStyle = 'rgba(56, 189, 248, 0.28)'`
- `lineWidth = 1`
- 可选虚线：`ctx.setLineDash([2, 3])`

元信息补充：

- 在 `traj-meta` 中新增：
  - 对应点数。
  - 平均对应误差。
  - 最大对应误差。

这些指标可复用当前 XY MSE 计算逻辑。

## 8. 图例交互方案

### 8.1 HTML 结构

将当前静态图例项改成按钮式元素，例如：

```html
<button class="traj-legend-item" data-layer="resamplePoints" type="button">
  <span class="legend-dot ..."></span>重采样点
</button>
```

### 8.2 CSS 状态

新增：

```css
.traj-legend-item {
  display: inline-flex;
  align-items: center;
  gap: 4px;
  background: transparent;
  border: 0;
  color: #aaa;
  padding: 2px 0;
}
.traj-legend-item.off {
  opacity: .35;
  text-decoration: line-through;
}
```

### 8.3 JS 绑定

新增：

```js
function initTrajLegend() {
  document.querySelectorAll('.traj-legend-item').forEach(item => {
    const layer = item.dataset.layer;
    item.classList.toggle('off', !trajLayers[layer]);
    item.setAttribute('aria-pressed', trajLayers[layer] ? 'true' : 'false');
    item.addEventListener('click', () => {
      trajLayers[layer] = !trajLayers[layer];
      item.classList.toggle('off', !trajLayers[layer]);
      item.setAttribute('aria-pressed', trajLayers[layer] ? 'true' : 'false');
      renderCachedTraj();
    });
  });
}
```

### 8.4 状态持久化

第一版可以只保存在内存中。若希望刷新页面后保留用户偏好，可以把 `trajLayers` 写入 `localStorage`：

- key：`internnav_traj_layers`
- 读取失败时使用默认值。

建议本次实现加入 `localStorage`，代价很低，体验更接近 Loss 图例。

## 9. 边界情况

1. 旧 JSONL 无 `gt_resample_points`：
   - 使用 `gt_traj` fallback。
2. 无 `gt_spline_traj`：
   - 不绘制样条曲线，不报错。
3. `pred_traj.length !== resample_points.length`：
   - 对应线连接 `min(length)` 个点。
   - `traj-meta` 显示 `对应点数: n / resampleLen vs predLen`。
4. 用户隐藏 GT 或 Pred：
   - 如果隐藏 `resamplePoints` 或 `pred`，对应线也应隐藏。
   - 如果只关闭 `correspondence`，重采样点和预测轨迹仍可独立显示。
5. 缩放和平移：
   - 图层切换只调用 `renderCachedTraj()`，不重置 `trajView`。

## 10. 验证计划

1. 启动监控页，打开已有 `traj_batches.jsonl`。
2. 检查默认显示：
   - 样条曲线可见。
   - 重采样点压在曲线上方。
   - 每个重采样点到同下标预测航点有连接线。
3. 点击每个图例项：
   - 对应图层立即隐藏/恢复。
   - 缩放和平移状态保持。
4. 切换 batch / sample：
   - 图层开关状态保持。
   - 元信息随样本更新。
5. 使用旧 JSONL 验证：
   - 没有 `gt_resample_points` 时前端仍能用 `gt_traj` 显示点。
   - 没有 `gt_spline_traj` 时面板不报错。

## 11. 实施顺序

1. 在 `monitor.html` 中增加 `trajLayers`、图例按钮样式和 `initTrajLegend()`。
2. 将 `drawTrajectory(...)` 改为接收 data object，或最小化修改参数列表并新增 `gtResamplePoints` 参数。
3. 在绘制逻辑中加入重采样点和对应关系线两个图层。
4. 在 `_write_traj_snapshot()` 中新增 `gt_resample_points` 字段。
5. 运行监控服务，使用浏览器检查图例切换、缩放、样本翻页和旧数据 fallback。

## 12. 预期效果

增强后，轨迹面板可以同时回答三个诊断问题：

- 样条监督点是否按弧长均匀分布。
- 模型预测的每个 waypoint 偏离对应监督点多少。
- 某个可视元素是否干扰观察，可以通过图例快速隐藏。

这样会比单纯叠加 GT / Pred 两条线更适合排查 waypoint 堆叠、局部漂移、终点偏差和重采样监督异常。
