# 前端轨迹可视化增强方案：障碍物层 / 导航目标点 / 轨迹终点

> 基于 Bridge-DP 实际代码分析，确保坐标系对齐、尺度不失真、数据语义正确。

---

## 一、现状分析

### 1.1 当前前端可视化内容

[`monitor.html`](../scripts/train/templates/monitor.html) 的 `drawTrajectory()` 函数目前只绘制：

| 元素 | 颜色 | 数据来源 |
|------|------|---------|
| 先验轨迹 | 灰色虚线 | `prior_traj` |
| 真值轨迹 | 绿色实线 | `gt_traj` |
| 预测轨迹 | 蓝色实线 | `pred_traj` |
| θ_g 方向箭头 | 绿/橙虚线 | `theta_g` |

**缺失**：障碍物点云投影、导航目标点标记、轨迹终点标记。

### 1.2 数据链路梳理

```
BridgeDP_Base_Dataset.__getitem__()
    ├── pred_actions (归一化, xy/5.0, θ/π)  → batch_labels
    ├── prior_traj   (归一化)                → batch_prior
    ├── point_goal   (归一化)                → batch_pg
    ├── theta_g      (原始弧度, 未归一化)    → batch_theta_g
    └── obstacle_points (世界坐标系, 米)     → 未传入 batch

BridgeDPTrainer._write_traj_snapshot()
    ├── gt_traj   ← batch_labels  (归一化坐标)
    ├── pred_traj ← _denormalize_action(naction)  (物理坐标, 米)  ← 尺度不一致！
    ├── prior_traj← batch_prior   (归一化坐标)
    └── theta_g   ← batch_theta_g (原始弧度)

→ 写入 checkpoints/{exp}/logs/traj_batches.jsonl
```

### 1.3 坐标系问题（核心难点）

| 数据 | 坐标系 | 尺度 |
|------|--------|------|
| `gt_traj` / `prior_traj` | 局部坐标系（以 memory_start_choice 帧为原点） | 归一化：xy/5.0, θ/π |
| `pred_traj` | 局部坐标系（同上） | 物理坐标（米）|
| `point_goal` (batch_pg) | 局部坐标系（同上） | 归一化：xy/5.0, θ/π |
| `obstacle_points` | **世界坐标系** | 物理坐标（米）|

**关键结论**：
1. `gt_traj` 与 `pred_traj` 当前存在尺度不一致（前者归一化，后者物理坐标），需要统一。
2. `obstacle_points` 在世界坐标系，无法直接与局部轨迹叠加，需要坐标变换。
3. 最简可行方案：**在 JSONL 中统一使用物理坐标（米）**，障碍物点做局部化变换后写入。

---

## 二、实现方案

### 方案选择：统一物理坐标 + 障碍物局部化

**核心原则**：
- 所有写入 JSONL 的轨迹数据统一反归一化为物理坐标（米）
- 障碍物点云在 Trainer 中做世界→局部坐标变换，写入 JSONL
- 导航目标点 = `point_goal` 反归一化后的 (x, y)
- 轨迹终点 = `gt_traj[-1]`（已有，只需在前端标注）
- 前端 `drawTrajectory()` 新增三层绘制逻辑

#### 3.1.3 障碍物点的处理策略

**问题**：`obstacle_points` 在世界坐标系，而轨迹在局部坐标系。Dataset 的 `__getitem__` 中已经做了 `relative_pose` 变换，但障碍物点没有随之变换。

**方案**：在 Dataset 中新增 `obstacle_pts_local` 字段，或在 Trainer 中通过 `batch_pg` 的方向信息做近似裁剪。

**推荐方案（最小改动）**：在 `BridgeDP_Base_Dataset.__getitem__` 中，将障碍物点变换到局部坐标系后，采样最近的 N 个点写入 batch。

```python
# 在 __getitem__ 末尾（第 720 行附近）新增
# 障碍物点局部化：取以 memory_start_choice 为原点的局部坐标
if trajectory_obstacle_points.shape[0] > 0:
    _, obs_local = self.relative_pose(
        trajectory_extrinsics[memory_start_choice][0:3, 0:3],
        trajectory_extrinsics[memory_start_choice][0:3, 3],
        np.eye(3),
        trajectory_obstacle_points,   # (N, 3) 世界坐标
        trajectory_base_extrinsic,
    )
    # 只保留水平面 (x, y)，取最近 512 个点（按距离排序）
    obs_xy = obs_local[:, 0:2]
    dists = np.linalg.norm(obs_xy, axis=-1)
    top_k = min(512, obs_xy.shape[0])
    idx = np.argsort(dists)[:top_k]
    obs_local_xy = obs_xy[idx].astype(np.float32)  # (K, 2)
else:
    obs_local_xy = np.zeros((0, 2), dtype=np.float32)

obstacle_pts = torch.tensor(obs_local_xy, dtype=torch.float32)  # (K, 2)
```

**注意**：由于每个样本的障碍物点数量不同，`collate_fn` 需要用 padding 或 list 处理。推荐用 list 存储，不进入 `torch.stack`。

#### 3.1.4 新增辅助方法 `_denorm_batch`

```python
def _denorm_batch(self, batch_tensor):
    """将归一化的 batch 轨迹/目标点反归一化为物理坐标（米/弧度）。"""
    t = batch_tensor.detach().cpu().clone()
    t[..., 0:2] = t[..., 0:2] * 5.0
    t[..., 2]   = t[..., 2]   * 3.14159
    return t
```

### 3.3 Trainer `_write_traj_snapshot` 完整修改

```python
def _write_traj_snapshot(self, gt_phys, pred_phys, prior_phys, gt_labels,
                          batch_theta_g=None, batch_nav_goal=None,
                          batch_obstacle_pts=None):
    """写入 JSONL，所有轨迹统一使用物理坐标（米/弧度）。"""
    if not hasattr(self, '_log_step_count'):
        return
    try:
        log_dir = Path(self.args.output_dir).parent / 'logs'
        log_dir.mkdir(parents=True, exist_ok=True)
        batch_file = log_dir / 'traj_batches.jsonl'

        B = gt_phys.shape[0]
        theta_g_list = (batch_theta_g.detach().cpu().view(-1).tolist()
                        if batch_theta_g is not None else [None] * B)
        nav_goal_list = (batch_nav_goal.detach().cpu()[:, 0:2].tolist()
                         if batch_nav_goal is not None else [None] * B)
        obs_list = ([pts.detach().cpu().tolist() if hasattr(pts, 'detach')
                     else pts.tolist() for pts in batch_obstacle_pts]
                    if batch_obstacle_pts is not None else [[] for _ in range(B)])

        record = {
            "batch_idx": self._log_step_count,
            "step":      self._log_step_count,
            "samples": [
                {
                    "gt_traj":      gt_phys[i].tolist(),
                    "pred_traj":    pred_phys[i].tolist(),
                    "prior_traj":   prior_phys[i].tolist(),
                    "theta_g":      theta_g_list[i],
                    "nav_goal":     nav_goal_list[i],
                    "obstacle_pts": obs_list[i],
                }
                for i in range(B)
            ],
        }
        with open(batch_file, 'a') as f:
            f.write(json.dumps(record) + '\n')
    except Exception as e:
        print(f"[TrajectoryVis] Failed to write traj snapshot: {e}")
```

## 四、坐标系对齐验证

### 4.1 统一坐标空间

修改后，JSONL 中所有字段均为**局部坐标系物理坐标（米）**：

| 字段 | 坐标系 | 单位 | 变换方式 |
|------|--------|------|---------|
| `gt_traj` | 局部（memory_start_choice 为原点） | 米 | `batch_labels * [5, 5, π]` |
| `pred_traj` | 局部 | 米 | `_denormalize_action(naction)` |
| `prior_traj` | 局部 | 米 | `batch_prior * [5, 5, π]` |
| `nav_goal` | 局部 | 米 | `batch_pg[:, 0:2] * 5.0` |
| `obstacle_pts` | 局部 | 米 | `relative_pose(world → local)` |

### 4.2 尺度一致性

- 轨迹范围：典型 0~10m（归一化前），反归一化后 xy 范围 ≈ [-10, 10]m
- 障碍物点：经 `relative_pose` 变换后与轨迹在同一局部坐标系
- 导航目标：`batch_pg * 5.0` 后与轨迹同尺度

### 4.3 前端坐标映射

前端 `tx(x)` / `ty(y)` 函数基于所有点的 bounding box 自适应缩放，只要所有数据在同一坐标系，缩放就自动对齐。

**注意**：障碍物点可能分布范围很广（整个场景），需要在写入时做距离裁剪（取最近 512 个点），避免 bounding box 被远处障碍物撑大导致轨迹显示过小。

## 六、风险与注意事项

### 6.1 `relative_pose` 对障碍物点的适用性

[`relative_pose`](../internnav/dataset/bridgedp_lerobot_dataset.py:385) 的批量路径（`len(T_world.shape) > 1`）接受 `(N, 3)` 输入，可以直接处理障碍物点数组。但需要注意：

- 障碍物点是**世界坐标系**的 3D 点，`relative_pose` 的 `T_world` 参数期望的是世界坐标系下的平移向量
- 障碍物点的 `R_world` 应传 `np.eye(3)`（点没有旋转）
- 变换后取 `[:, 0:2]` 得到水平面 (x, y)

### 6.2 障碍物点数量控制

原始点云可能有数万个点，全部写入 JSONL 会导致文件过大。建议：
- 取距离起点最近的 **512 个点**（已在方案中体现）
- 或按网格下采样（voxel grid，间距 0.5m）

### 6.3 向后兼容性

旧的 JSONL 文件中没有 `nav_goal` 和 `obstacle_pts` 字段，前端需要做空值检查（`if (navGoal && ...)` 已体现）。

### 6.4 `_write_traj_snapshot` 中的 gt_labels 参数

原函数第 4 个参数 `gt_labels` 在当前代码中未被使用（写入 record 时没有用到），可以移除或保留作为调试用途。
